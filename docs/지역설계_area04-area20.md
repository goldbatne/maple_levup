# 지역 설계 — area_04 ~ area_20 (Lv31 ~ Lv200)

> **상태: 대표 검증 대기.** 아직 아무것도 구현하지 않았다. 이 문서는 **검증받을 설계**다.
> 승인되면 area_04부터 한 지역씩 T36/T37과 같은 3단계(데이터 → 맵·모델 → 스킬)로 만든다.
> 작성: 2026-08-29

지역 20칸은 2026-08-28 대표 확정이다. 1~3번(헤네시스·엘리니아·페리온)은 이미 있고,
여기는 **남은 17개**를 설계한다.

## 0. 규격 — area_03(엘리니아)을 정본으로 삼는다

가장 최근에 만든 area_03이 가장 단순하고 깨끗하다. 17개를 전부 이 꼴로 찍는다.

| | 값 |
|---|---|
| 방 수 | **5개** (사냥 4 + 보스 1) |
| 연결 | 한 줄로 이어진다 (진입방 → 동 → 동 → 동 → 보스) |
| 몬스터 레벨 | 대역 시작 기준 **+0 / +2 / +4 / +7 / +9** |
| 마릿수 | **4 / 4 / 5 / 5 / 1** |
| 방 이름 | **원작 맵 이름 그대로** (T26-5 규칙: 방과 몬스터는 같은 출처에서) |
| 보스 | `room_type=boss` 한 칸으로 배율·재등장·귀환 포탈이 따라온다 |

방 id·맵 이름은 **두 자리 지역번호 + 방번호**로 간다 — 기존(`r_01`/`r_11`/`r_21`)은
한 자리라 area_10에서 부딪힌다.

```
area_04 → r_041 ~ r_045 / map041 ~ map045
area_20 → r_201 ~ r_205 / map201 ~ map205
```

## 1. 마을 출입 — **모든 지역은 마을 동쪽 문 하나로 나간다**

> 대표 정정 (2026-08-29): *"1번은 그냥 마을에서 우측으로 가자는거였잖아"* — 맞다.
> 내가 **방향 넷을 지역에 하나씩 배정하는 문제**로 잘못 봤다. 원래 설계는 그게 아니다.

2026-08-10 설계 그대로다: **마을 동쪽 문(지역 선택 창)이 유일한 출입구**이고,
어느 지역으로 가든 그 문 하나를 쓴다. 지역마다 방향을 하나씩 줄 이유가 없다.

지금 `r_town`에 north(페리온) / south(엘리니아)가 박혀 있는 것은 **길이 아니라
검증기를 통과하려고 넣은 껍데기**다. T26-1에 그렇게 적혀 있다:

> `r_town.conn_north = r_11`을 **데이터에만 넣고 마을에 북쪽 포탈 엔티티는 놓지 않았다** —
> `GameDataVerify`의 양방향 검사는 통과하고, 마을에서 걸어서 페리온에 갈 길은 생기지 않는다.

그리고 동쪽 문마저 **이동에 안 쓰인다** — `r_town`의 `Portal_E`에는 `RoomPortal`이 아니라
`TownGate`가 붙어 있다. 즉 **`r_town`의 conn 네 칸은 전부 장식이다.**

### 그래서 이렇게 통일한다

| | |
|---|---|
| **들어갈 때** | 마을 **동쪽 문** → 지역 선택 창 → 그 지역의 진입 방 (지금과 같다) |
| **나올 때** | 진입 방에서 **서쪽으로 걸어 나오면 마을** — 17개 지역 전부 `conn_west = r_town` |
| `r_town`의 conn | **네 칸 모두 비운다** |

고칠 곳은 `GameDataVerify.VerifyRooms` 한 군데다 — **대상이 마을이면 역방향을 묻지 않는다.**

```lua
elseif targetRoom.room_type == "town" then
    -- 마을은 방향으로 들어가는 곳이 아니다. 어느 지역이든 **동쪽 문 하나**로 들어가고
    -- (지역 선택 창, 2026-08-10), 나올 때만 서쪽으로 걸어 나온다.
    -- 마을이 스무 지역을 전부 가리킬 방향은 애초에 없고, 있어도 쓰이지 않는다.
    log("    " .. dir .. " -> " .. target .. " (마을 — 역방향 면제)")
elseif targetRoom.connections[back] ~= id then
```

**게임 동작은 안 바뀐다.** 기존 세 지역도 같이 정리된다 (페리온은 남쪽 → 서쪽,
엘리니아는 북쪽 → 서쪽으로 통일). 이제 지역을 몇 개 만들든 걸리지 않는다.

## 2. 지역 해금 레벨 — **✅ 확정: 대역이 시작되기 직전 레벨에 연다**

> 대표 결정 (2026-08-29): *"2번 그대로 가자 **왜냐하면 그게 레벨 구간이니까**"*
> — 대역 시작 직전에 열어야 **그 대역이 실제로 거기서 노는 레벨 구간**이 된다.

지금은 **대역을 다 지난 뒤에야 열린다** — 엘리니아 몬스터가 Lv11~20인데 문이 Lv20에 열려서,
정작 그 구간에는 못 간다. 한 칸씩 당긴다.

| 지역 | 대역 | 해금 레벨 | 지금 |
|---|---|---|---|
| area_03 엘리니아 | 11~20 | **Lv10** | Lv20 → 고친다 |
| area_02 페리온 | 21~30 | **Lv20** | Lv30 → 고친다 |
| area_04 커닝시티 | 31~40 | **Lv30** | (신규) |
| area_05 노틸러스 | 41~50 | **Lv40** | (신규) |
| … | … | … | |
| area_20 황혼의 페리온 | 191~200 | **Lv190** | (신규) |

규칙 한 줄: **대역 `[10k+1, 10k+10]`인 지역은 `Lv 10k`에 열린다.**
`LandmarkTable` 기존 2줄 수정 + 17줄 추가.

## 3. 17개 지역 배치

몬스터는 **전부 MSW 리소스 팩 존재를 확인**했다. 괄호 안이 팩 id다 —
T37-1b에서 이벤트/그란디스 몬스터를 엘리니아에 넣었다가 지역 하나를 다시 만들었기 때문에,
이번엔 **고른 85종을 전부 검색해 대역을 봤다.** (`9xxxxxx`=이벤트, `24~26xxxxx`=그란디스 → 제외)

원작 레벨과 우리 레벨이 다른 것은 **의도된 것**이다 — 2026-08-28 설계 변경 이력:
*"몬스터는 원작에서 가져오되 레벨은 우리 사다리에 맞춘다."*

## 6. 제안 — 포획 스킬에 **패시브**를 붙인다 (설계 변경, 승인 필요)

> 대표 제안 (2026-08-29): *"포획스킬을 패시브 스킬로도 추가해보는것도 어떠냐?
> 일정 능력치가 올라가는거로 해서 이게 환생하면 1레벨에서 뭔가 잘 안잡히는 느낌이네"*

### 재 봤다 — 그 느낌이 맞다. 환생해도 Lv1 구간에는 보상이 하나도 안 나온다

환생하면 남는 것: 스킬 컬렉션 · 슬롯 수 · 차수 · 장비 · 개방 지역.
사라지는 것: 레벨 · 분배 스탯.

환생 보상은 둘인데(2026-08-21) **둘 다 Lv1에서는 안 보인다**:

| 보상 | 왜 Lv1에서 안 보이나 |
|---|---|
| 레벨업당 스탯 `5 + floor(최고/10)` | **레벨이 올라야** 받는다. Lv1에는 0P다 |
| 사냥방 몬스터 `+floor(최고/10)`마리 | 4마리가 7마리 되는 것뿐 — 되레 위험해 보인다 |

그래서 **환생 직후의 몸은 신규 계정과 정확히 같다** (장비를 뺀다면).

### ⚠⚠⚠ 그런데 재 봤더니 훨씬 심했다 — 처음 적은 수치가 틀렸다

여기 처음에 *"물리 공격력 70 / HP 1200 / 3.7대"*라고 적었는데 **전부 틀렸다.**
`player_base_atk`(10)를 "STR 10"으로 잘못 읽어 계산한 값이었다.
실제로는 **`GetStr()`이 분배분만 돌려주고 기본값은 없다.** 런타임 실측:

| | 값 | Lv1 달팽이(HP 144 · DEF 80 · ATK 157) |
|---|---|---|
| **신규/환생 직후 Lv1** (분배 0 · 장비 0 · 컬렉션 0) | 물공 **10** · 방어 10 · HP 1000 | **잡는 데 108대** / 맞고 버티는 5.6대 |

**108대다.** 5.6대 맞으면 죽으므로 **첫 달팽이를 못 잡는다.**
직전까지 Lv30~40이던 사람이 여기로 떨어지는 것이 *"잘 안 잡히는 느낌"*의 정체다 —
느낌이 아니라 **실제로 안 잡힌다.**

### 원인은 패시브가 아니라 T27-2에서 안 따라 올라간 기본값이다

T27-2가 스탯 계수를 **5배**로 올릴 때(1P당 +1 → +5) **`player_base_atk`·`_int`·`_def`
셋(각 10)을 안 올렸다.** 옛 체계에서 기본 10은 "1P를 10번 찍은 것"이었는데,
지금은 **2P어치**다. 반대로 몬스터 DEF 기본은 T28에서 5 → **80**이 됐다.

⚠ **이건 패시브와 별개의 문제다.** 패시브는 이 구간을 메우지만 고치지는 못한다:

| | 물공 | 달팽이 잡는 대수 |
|---|---|---|
| 신규 Lv1 | 10 | **108대** |
| 패시브 3종 만작 (지금) | 24 | 21.7대 |
| 패시브 40종 만작 (20지역 다) | 248 | 0.6대 |
| *(대조)* Lv10 STR 몰빵 45P | 235 | 0.7대 |

**패시브를 20지역치 다 모으면 Lv1이 Lv10과 같아진다** — 환생 보상으로는 적절하다.
하지만 **컬렉션이 없는 신규 계정은 여전히 108대**다.

> **별도 결정이 필요하다.** `player_base_atk/int/def`를 T27-2 배율(×5)에 맞춰
> **50 정도로** 올리면 신규 Lv1이 물공 50 → 달팽이 **9대**가 된다.
> 밸런스 변경이라 **지시 없이 안 건드렸다.**

거기에 T34에서 `exp_base`가 20 → 60이 되어 **Lv1→2에 12마리**가 필요하다.

### 제안: 포획한 종의 힘이 몸에 남는다

**보유한 몬스터 스킬 1종당 해당 스탯 +1P 상당**을 준다. 어느 스탯인지는
**이미 있는 컬럼에서 유도한다** — 새 컬럼을 안 만든다.

| 스킬 | 주는 스탯 |
|---|---|
| `skill_kind = attack` · 계수 스탯 ATK | **STR** |
| `skill_kind = attack` · 계수 스탯 INT | **INT** |
| `skill_kind = defense` | **DEX** |

지금 몬스터 스킬 17종 = **STR +9 / INT +5 / DEX +3**.

### 수치 — 초반에만 크고 후반엔 저절로 사라진다

**Lv1 (환생 직후, 컬렉션 17종)**

| | 지금 | 패시브 후 |
|---|---|---|
| STR / DEX / INT | 10 / 10 / 10 | **19 / 13 / 15** |
| 물리 공격력 | 70 | **121** |
| 최대 HP | 1200 | **1380** |
| Lv1 몬스터 잡는 대수 | 3.7대 | **1.6대** |
| Lv1 몬스터 맞고 버티는 대수 | 10.4대 | **13.4대** |

**Lv50 (같은 컬렉션)**

| | 지금 | 패시브 후 |
|---|---|---|
| 물리 공격력 (STR 몰빵) | 1295 | 1340 |
| Lv50 몬스터 잡는 대수 | 2.1대 | **2.0대** |

**이게 이 설계의 핵심이다.** 분배 포인트가 레벨당 5씩 쌓이므로 +17은
Lv1에선 컸다가 Lv50이면 6.8%가 된다. **상한을 안 둬도 저절로 감쇠한다.**

### ⚠ 게이트에는 안 센다

`RoomGate`의 `STAT_TOTAL`은 `GetAllocatedTotal()` = `StatStr+StatDex+StatInt+StatLuk`,
즉 **실제로 분배한 포인트**만 본다. 패시브를 그 프로퍼티에 더하면
**컬렉션만으로 문이 열린다** — 2026-08-12 결정("게이트가 재는 것은 성장이어야 한다")과 부딪힌다.

→ **장비와 똑같이 다룬다.** `GetEquipBonus` 옆에 `GetCollectionBonus`를 두고
`GetTotalAtk/Int/Def/Luk`·`GetMaxHp`에만 얹는다. `GetAllocatedTotal`은 안 건드린다.
**이미 장비가 쓰고 있는 이음매라 새로 만들 구조가 없다.**

### ✅ 중복 장수를 센다 (대표 결정)

> *"패시브 중복으로 잡으면 오히려 **다음 지역에 대한 완화제**를 줄 수 있을거야.
> 여기에서 내가 의도한건 **환생당 포인트를 늘릴까** 했는데 1이 하나씩 늘어나면 더 강해져서,
> 차라리 패시브로 제공하는게 **얻는 재미와 성장의 경험**을 얻을 수 있거든"*

내 권장(중복 안 셈)을 뒤집는 결정이고, **근거가 더 낫다**:

- **지금 지역에서 더 사냥할 이유가 생긴다.** 중복을 모으면 다음 지역이 쉬워진다 —
  막히면 갈아서 넘는 길이 열린다. "완화제"라는 말 그대로다.
- **환생당 포인트를 늘리는 안보다 낫다.** 그건 그냥 숫자가 커지는 것이고,
  이건 **포획해서 얻는 재미**가 그대로 힘이 된다. 코어와 엔진을 같이 민다.

### ⚠ 그런데 장당 1P로 두면 만작에서 무너진다 — 재 봤다

`skill_stack_max = 5`이므로 종당 최대 5장이다.

**안 A · 장당 1P (그대로)**

| | 준 포인트 | 물리 공격력 | 결과 |
|---|---|---|---|
| 17종 1장씩 | +17P | 121 | Lv1 몬스터 **1.6대** ✓ |
| 17종 만작(85장) | +85P | 325 | Lv1 몬스터 **0.5대** = 한 방 |
| 85종 만작(425장) | **+425P** | **1345** | ⚠⚠ **Lv1인데 Lv50 STR 몰빵(1295)과 같다** |

20지역을 다 모으면 **Lv1에서 Lv50 사냥터가 그대로 돈다.** 완화제가 아니라 대체재가 된다.

**안 B · 첫 장 1P + 추가 장마다 0.25P (권장)**

| | 준 포인트 | 물리 공격력 | 결과 |
|---|---|---|---|
| 17종 1장씩 | +17P | 121 | Lv1 몬스터 **1.6대** ✓ |
| 17종 만작(85장) | +34P | 172 | Lv1 몬스터 **1.0대** ✓ |
| 85종 만작(425장) | +170P | 580 | Lv50 몬스터 **7.2대** — 되긴 하되 힘들다 ✓ |

**만작 1종 = 2P (2배).** T15-2의 계수 강화가 `1.0 → 1.8`인 것과 **같은 모양**이라
중복의 값어치가 두 축에서 일관된다.

**두 값 다 `GameBalance` 칸으로 뺀다** — `collection_passive_first` / `collection_passive_extra`.
플레이하며 조절할 수 있어야 하고, 지역이 늘 때마다 다시 재야 하는 값이다.

> **안 A / 안 B 중 하나만 골라 주시면 된다.** 나머지는 다 정해졌다.

### 이건 코어를 강화한다

CLAUDE.md의 판단 기준은 *"코어(세계를 한 방씩 헤쳐나가는 맛)를 강화하나,
엔진(숫자가 오르는 손맛)을 강화하나"*다. 이건 **둘 다**다 —
포획이 그 회차의 무기일 뿐 아니라 **다음 회차의 몸**이 되고,
"환생은 리셋이 아니라 더 깊은 세계를 여는 열쇠"(기획서 §2)가 수치로 실현된다.

**패시브는 지역 제작보다 먼저 넣는다.** 85종이 다 붙은 뒤에 밸런스를 정하면 되돌리기 어렵다.

## 8. 패시브는 **절반만** — 나머지는 액티브·버프로 남긴다

> 대표 지시 (2026-08-29): *"포획 패시브는 절반정도 지정해주면 좋을거 같아,
> **버프·액티브가 존재해야 하니까**"*

내가 §6에서 **모든 포획 스킬이 패시브를 준다**로 설계한 것을 고친다. 그러면
슬롯에 낄 스킬과 안 낄 스킬이 갈리지 않아 **"무엇을 끼울지가 곧 빌드"**라는 핵심 설계가 얇아진다.

### 지역당 5종 = 액티브 3 + 패시브 2

| | 몇 종 | 슬롯 | 하는 일 |
|---|---|---|---|
| **액티브** (공격) | 2 | **먹는다** | 지금과 같다 |
| **액티브** (방어·버프) | 1 | **먹는다** | 실드 등 (2026-08-16: 방어도 같은 슬롯을 먹는다) |
| **패시브** | **2** | **안 먹는다** | **보유만 해도 항상 켜진다** |

**패시브가 슬롯을 안 먹는 것이 핵심이다.** 그래야 §6의 목적(환생 직후 완화)이 성립하고,
슬롯은 여전히 액티브끼리 경쟁하는 자리로 남는다.

### 데이터 — 새 컬럼 둘

`skill_kind`에 **`passive`**를 더한다 (지금 `attack` / `defense`).

⚠ **주는 스탯을 `scaling_stat`에 넣으면 안 된다.** 그 칸은 **파생 수치 이름**
(ATK/INT/LUK)을 쓰는데 패시브가 주는 것은 **분배 스탯**(STR/DEX/INT/LUK)이다 —
CLAUDE.md가 경고한 **이름 체계가 둘인 함정**에 정확히 걸린다. 컬럼을 따로 둔다.

| 새 컬럼 | 값 |
|---|---|
| `passive_stat` | `STR` / `DEX` / `INT` / `LUK` |
| `passive_value` | 1장당 포인트 (기본 1) |

액티브 줄은 두 칸이 비고, 패시브 줄은 `coefficient`·`range` 등이 빈다.
`EquipMonsterSkill`이 `skill_kind == "passive"`면 거절하고, 장착 창은 **별도 탭**에 모은다.

### ⏳ 기존 17종은?

지금 17종은 전부 액티브이고 **아이콘·이펙트·소리가 다 붙어 있다.** 패시브로 돌리면
이펙트·소리가 안 쓰인다.

- **(권장) 지역당 1종씩만 돌린다** — 헤네시스·엘리니아·페리온에서 각 1종.
  환생 직후 완화가 **초반 회차에도** 생기고, 버리는 자산은 3종뿐이다
- 그대로 둔다 — 아무것도 안 버리지만, 3지역만 돈 사람은 패시브가 0이라 §6의 목적이 안 산다
- 각 2종씩 돌린다 (7종) — 일관되지만 이펙트 7종이 논다

> **어느 것으로 갈지, 그리고 돌릴 종을 대표가 골라 주시면 좋겠다.**

## 9. 게이트 — 레벨 · 보스 · 스탯을 한 줄로 세운다

> 대표 지시 (2026-08-29): *"보스 클리어와 해금 레벨, 스탯 다 적절히 넣어줘야 할거 같아
> **일직선으로 성장하도록** 말이지"*

세 관문을 **지역마다 같은 자리**에 놓는다. 대역이 `[10k+1, 10k+10]`인 지역 기준:

| 순서 | 어디 | 무엇 | 값 |
|---|---|---|---|
| 1 | (지역 밖) | **해금 레벨** — `LandmarkTable` | `Lv 10k` |
| 2 | **진입 방** `r_N1` | **보스 클리어** — `gate_type=boss` | 직전 지역의 **보스방 id** |
| 3 | **3번째 방** `r_N3` | **스탯** — `gate_type=stat` `STAT_TOTAL` | `5 × (10k+3)` |
| 4 | 보스 방 `r_N5` | 없음 | 앞 방을 지나온 것이 조건이다 |

**셋이 서로 다른 것을 묻는다** — 레벨은 시간, 보스는 실력, 스탯은 **실제로 찍었는가**
(`GetAllocatedTotal`은 미분배 포인트를 안 쳐준다).

### 실제 값

| 지역 | 대역 | 해금 Lv | 보스 게이트 | 스탯 게이트 |
|---|---|---|---|---|
| area_04 커닝시티 | 31~40 | 30 | `r_15` (페리온 보스) | **165** |
| area_05 노틸러스 | 41~50 | 40 | `r_045` | 215 |
| area_06 지하 하수도 | 51~60 | 50 | `r_055` | 265 |
| area_07 슬리피우드 | 61~70 | 60 | `r_065` | 315 |
| … | | | 직전 지역 보스방 | `5×(10k+3)` |
| area_20 황혼의 페리온 | 191~200 | 190 | `r_195` | **965** |

기존 `r_14`의 `STAT_TOTAL 170`이 Lv35에 해당하는데, 이 공식이 area_04에 주는 값이
**165**다 — **이미 쓰던 감각과 맞는다.** 지어낸 값이 아니라 기존 값에서 뽑은 식이다.

⚠ `gate_type=boss`는 **영구 기록**을 본다(`HasEverClearedBoss`, 2026-08-16) —
환생해도 이미 연 문은 안 닫힌다. 일직선 성장에 맞는 성질이다.

## 10. ⚠⚠ 맵 — **원작 맵을 그대로 가져올 수 있다** (이번에 확인했다)

> 대표 지시: *"지역은 다 맵을 만들어줘 **색도 각 맵에 콘셉트에 맞게** 해주고"*

### 먼저: 우리 타일셋으로는 "콘셉트에 맞는 색"이 안 나온다

워크스페이스의 타일셋은 **`RectTileData_Henesys` 하나뿐**이고 134종이 전부
`soil`(61) / `stone`(57) / `water`(16)다. 그중 **물 16종은 전부 통과 불가**이고,
바닥으로 깔 수 있는 것은 T26-4에서 확인한 **넷**뿐이다:

| 쓸 수 있는 바닥 | 색 |
|---|---|
| `soil_1`~`soil_5` | 잔디 초록 |
| `soil_59`~`soil_61` | 갈색 흙 (자갈 밀도로 3단계) |
| `stone_1`·`stone_2` | 회색 조약돌 |
| `stone_4`·`stone_5` | 돌 포장 |

**지하철·바다·설산·사막·우주선·기계를 이 넷으로 칠해야 한다.** 파란 바다도,
흰 눈밭도, 금속 바닥도 만들 수 없다. `.tileset`은 편집 대상이 아니고(AGENTS.md),
원작 타일은 사이드뷰용 `MapleTileSetData`라 호환되지 않는다(T26-4).

### 그런데 — Maker에 **원작 맵 7,948개**를 가져오는 도구가 있다

`maker_list_maplestory_maps` / `maker_import_maplestory_map`.
**설계에 적은 방들이 원작 id로 그대로 있다:**

| 우리 방 | 원작 맵 | id |
|---|---|---|
| 방치된 공사장 | Abandoned Construction Site | `103010100` |
| 선로를 따라서 | Along the Railway | `103020100` |
| 환승구역 | Transfer Area | `103020200` |
| 1호선 3구간 | Line 1 Area 3 | `103020320` |
| 방황의 늪 | The Swamp of Despair | `103030000` |

15개 지역 중 **14개가 목록에 있다** (지구방위본부만 못 찾았다).

### 실제로 넣어 봤다 — 된다

버릴 맵을 만들어 `103020100`(선로를 따라서)을 가져왔다. **지하철 차량·비계·배관·
사다리·배경이 전부 그대로 들어온다.** `MapLayerComponent`(모든 맵에 이미 있는
`MapleMapLayer` 엔티티) 위에 레이어로 얹힌다. 시험 뒤 워크스페이스는 원상복구했다.

### ⚠ 그래서 결정이 필요하다 — 이건 **보는 문제**라 대표가 판단해야 한다

원작 맵은 **사이드뷰 그림**이고 우리는 **탑다운**이다. 그림 자체는 훌륭한데,
탑다운으로 걸어 다니면 **지하철 차량 위를 떠다니는 것처럼** 보일 수 있다.
지역마다 결과가 다를 것이다 — 사막·황야·동굴 바닥은 잘 맞고, 지하철·건물 내부는 어색할 수 있다.

| 안 | 어떻게 | 대가 |
|---|---|---|
| **A. 우리 타일만** | 넷으로 17개 테마를 칠한다. 자갈 밀도·잔디 얼룩으로 결만 다르게 | **색이 콘셉트에 안 맞는다.** 사막도 갈색, 기계무덤도 회색 |
| **B. 원작 맵 가져오기** | 배경·장식을 원작에서 통째로 | **원작 그대로의 색.** 사이드뷰↔탑다운 어긋남 |
| **C. 섞는다 (권장)** | 걷는 **바닥은 우리 RectTile**, **배경·장식만 원작** | 지역마다 어울리는지 봐야 한다 |

**한 지역(area_04 커닝시티)만 안 C로 만들어 보여 드리고, 그걸 보고 나머지 16개를
정하는 것**을 권한다. 85개를 다 만든 뒤에 "안 맞는다"가 나오면 되돌릴 수 없다.

### ⚠ 맵을 복제할 때 놓치기 쉬운 곳 (이번에 걸렸다)

`MapBuilder.rename`은 **엔티티 이름만 바꾸고 `.map`의 `EntryKey`는 안 바꾼다.**
그대로 두면 Maker가 못 읽는다:

```
[LEA-3015] CannotLoad : Entry key가 중복되어 파일 로드에 실패했습니다.
                        중복 EntryKey = 'map://map01'
```

**85개를 복제할 것이므로 `EntryKey`를 같이 가는 절차를 박아 둬야 한다.**

## 11. 순서

1. **포획 패시브** (§6 · §8) — 지역을 만들기 전에. 85종이 붙은 뒤엔 못 되돌린다
2. **마을 출입 정리** (§1) + **해금 레벨 정정** (§2) + **게이트 배치** (§9) — 셋 다 작고, 선행 조건
3. **area_04 커닝시티 한 지역만 먼저** — 맵을 §10의 안 C로 만들어 **보여 드린다**
4. 대표가 보고 나머지 16개 방식을 확정 → 한 지역씩
5. 20지역이 다 선 뒤 **직업별 보스** (대표: *"지역보스를 다 만들어주면 그 이후에 생각해볼게"*)

### 지금 대표가 정해 주실 것

| | | 내 권장 |
|---|---|---|
| **A** | 패시브 장당 값 (§6) — 안 A(1P) / 안 B(첫 장 1P + 추가 0.25P) | **안 B** |
| **B** | 기존 17종 중 패시브로 돌릴 것 (§8) | **지역당 1종씩 3종** |
| **C** | 맵 만드는 방식 (§10) — 안 A / B / C | **안 C, 단 커닝시티 하나 먼저 보고 결정** |

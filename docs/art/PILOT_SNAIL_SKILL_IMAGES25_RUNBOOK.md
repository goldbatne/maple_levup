# 달팽이 신규 스킬 Images 2.5 파일럿 런북

> 상태: **조사·설계 완료 / 이미지 생성·MSW 반입 미실행**
>
> 기준일: 2026-09-10
>
> 파일럿 대상: m_snail 달팽이 / 신규 스킬 가칭 **이슬 미끄럼길**
>
> 이 문서는 기존 s_mon_snail 몸통 박치기를 교체하는 명세가 아니다. 기존 스킬과 별개의 신규 스킬 아트를 외부 ChatGPT Images 2.5로 제작하고, 채택된 결과를 나중에 MSW에 반입하기 위한 단일 실행 문서다.

이 파일럿의 완료 범위는 다음과 같다.

1. 프로젝트와 MSW 공식 리소스에서 대상과 시각 레퍼런스를 확정한다.
2. 기존 메이플 스킬의 기능을 복제하지 않는 신규 스킬을 설계한다.
3. 외부 ChatGPT Images 2.5에 넣을 첨부 파일과 프롬프트를 고정한다.
4. 생성 결과의 분할·검수·MSW AnimationClip 반입 절차를 고정한다.
5. 실제 이미지 생성, Resource Storage 업로드, RUID 발급, SkillTable 반영은 이 문서 작성 단계에서 수행하지 않는다.

MSW 리소스 검색으로 확인한 공식 달팽이 팩은 **몬스터의 식별과 사용 가능한 동작 자산**을 증명한다. 그 결과만으로 달팽이의 성격·서사·마법 속성을 공식 설정이라고 단정하지 않는다.

### 외부 이미지 생성 도구에서 확인된 사실

- OpenAI는 ChatGPT Images 2.5가 참조 이미지의 세부 보존, 복잡한 레이아웃, 투명 배경, 다중 턴 수정에 대응한다고 설명한다. [Introducing ChatGPT Images 2.5](https://openai.com/index/introducing-chatgpt-images-2-5/)
- ChatGPT Images는 업로드한 이미지를 참조해 생성·수정할 수 있고, 투명 배경을 요청할 수 있다. [Creating images in ChatGPT](https://help.openai.com/en/articles/11084440-im)
- 여러 참조 이미지를 사용할 때는 작은 세트로 유지하고, 업로드 순서와 각 이미지의 역할을 프롬프트에 명시하는 편이 좋다. 수정은 한 번에 한 문제씩 요청하는 것이 일관성을 지키기 쉽다. [OpenAI Academy: Image generation](https://openai.com/academy/image-generation/)
- ChatGPT UI의 생성 결과가 요청한 **정확한 픽셀 수·완전한 4×2 셀 경계·8개의 개별 파일**을 항상 보장한다는 근거는 확인하지 못했다. 따라서 생성 시에는 비율과 구성을 요구하고, 채택 후 후처리 단계에서 정확한 1024×512 및 256×256 셀을 강제한다.

### MSW 반입에서 확인된 사실

- Resource Storage에는 Sprite를 직접 등록할 수 있고, Animation Clip은 전용 AnimationClip Editor로 제작해 등록한다. 스프라이트 피봇도 편집할 수 있다. [MSW 리소스 관리](https://maplestoryworlds-creators.nexon.com/ko/docs/?postId=690)
- AnimationClip Editor는 여러 스프라이트를 타임라인에 순서대로 배치하고, 각 프레임의 오프셋과 재생 속도를 조정한 뒤 업로드하여 RUID를 발급할 수 있다. 공식 안내상 스프라이트 파일은 한 번에 여러 장을 불러올 수 없으므로 각각 등록해야 한다. [MSW 애니메이션 만들기](https://maplestoryworlds-creators.nexon.com/ko/docs?postId=595)
- AnimationClip은 프레임 목록과 재생 속도를 가진 MSW 리소스다. [MSW AnimationClip API](https://maplestoryworlds-creators.nexon.com/apiReference/Misc/AnimationClip)
- EffectService는 AnimationClip RUID를 고정 위치 또는 엔티티에 붙여 한 번 재생할 수 있다. 다만 이 프로젝트의 현행 몬스터 다층 연출은 앞서 적은 SpriteRenderer 직접 재생 경로를 우선 사용한다. [MSW EffectService 안내](https://maplestoryworlds-creators.nexon.com/ko/docs/?postId=70)

## 2. [추정]

아래 내용은 공식 설정으로 확인된 것이 아니라, 프로젝트의 지역·전투 구조와 달팽이의 외형 및 일반적인 생물 특징을 연결한 **창작 판단**이다.

- 달팽이가 지나간 자리에 얇고 반짝이는 흔적을 남긴다는 생물적 이미지는 달팽이 신규 스킬의 소재로 자연스럽다.
- r_001 버섯마을 외곽과 r_006 작은 숲속 샛길이라는 프로젝트 맥락에는 거대한 마법진보다 이슬·풀빛·낮은 지면 흔적이 잘 맞는다.
- 저레벨 일반 몬스터의 스킬이므로 화면 전체를 덮는 폭발, 다중 색상 오라, 거대한 문양보다 짧고 작은 전방 이펙트가 전투 서열을 잘 전달한다.
- 8프레임, 약 0.56초, 256×256 셀은 현행 저레벨 보조 클립의 5~6프레임과 플레이어 스킬의 10프레임 사이에서 품질과 제작비를 절충한 파일럿 기준이다. 프로젝트의 절대 규격은 아니다.
- 신규 스킬의 제안 전투 수치와 판정 방식은 아트가 채택된 후 별도 밸런스 검증이 필요하다.

### 이 몬스터를 고른 이유

1. 프로젝트의 첫 전투 지역에 등장하는 레벨 1 일반 몬스터라서 파일럿 결과의 과한 화려함을 가장 엄격하게 판별할 수 있다.
2. 모델·스킬·지역 연결이 이미 안정되어 있어 아트 파이프라인만 분리해 검증하기 좋다.
3. 과거 달팽이 커스텀 스킬 아트의 성공·실패 기록이 있어, 같은 오류가 재발하는지 비교할 수 있다.
4. 현행 몸통 박치기와 다른 역할을 설계하면 “기존 스킬 복제 금지” 원칙을 실제로 시험할 수 있다.

참고로 메이플스토리 공식 초보자 스킬에는 달팽이 껍질을 던지는 **달팽이 세마리**가 존재한다. [메이플스토리 공식 스킬 안내](https://gi.maplestory.nexon.com/Guide/GameInformation/Skill/PathFinder) 이 파일럿은 그 기능이나 껍질 투사체를 복제하지 않는다.

### 공식 설정·지역 맥락과의 연결

- **확인된 연결:** 달팽이는 프로젝트의 메이플 아일랜드·리스항구 입문 지역에 배치된 레벨 1 일반 몬스터다.
- **창작 연결:** 숲길 바닥의 이슬과 달팽이가 남기는 얇은 흔적을 결합한다.
- **의도:** “달팽이가 갑자기 거대한 자연 마법을 쓴다”가 아니라, 몸과 지면에서 생기는 작은 현상이 공격으로 읽히게 한다.
- **배제:** 껍질을 던지거나 껍질 모양 에너지탄을 발사하지 않는다. 이는 공식 초보자 스킬과 겹치고, 과거 프로젝트에서 재료 아이템처럼 보였던 문제도 되풀이한다.

### 탑다운 RPG 사용 방식

아래는 아트와 함께 검증할 **제안 동작**이며 아직 구현 수치가 아니다.

1. 시전자의 발밑 앞쪽에서 작은 이슬 두세 방울이 모인다.
2. 바라보는 방향으로 낮고 좁은 흔적이 약 2월드 단위 뻗는다.
3. 흔적의 끝이 작게 튀는 순간 전방의 최대 3대상에 1회 피해를 준다.
4. 공격자는 돌진하지 않고, 흔적은 곧 작은 방울로 흩어져 사라진다.

### 플레이어가 획득했을 때의 활용 이미지

- 몸통 박치기보다 안전한 짧은 전방 정리기로 사용한다.
- 좁은 통로나 몬스터가 앞에 두세 마리 모였을 때 쓰는 입문형 범위기다.
- 큰 보스 기술처럼 화면을 장악하지 않고, “달팽이에게서 얻은 작고 재치 있는 기술”로 읽힌다.
- 공격자의 직업 무기나 자세에 의존하지 않아 여러 직업이 사용해도 어색하지 않다.

### 왜 신규 스킬인가

- 현행 몸통 박치기는 **시전자 자체가 전진하는 물리 돌진**이다.
- 이슬 미끄럼길은 **시전자는 멈춘 채 지면 흔적이 전방으로 형성되는 소형 범위 공격**이다.
- 공식 초보자 스킬 달팽이 세마리의 **껍질 소비·투척**도 사용하지 않는다.
- 기존 레퍼런스에서 빌리는 것은 프레임 밀도, 명암, 충돌 시점의 가독성뿐이며, 공격 구조·실루엣·색 배치는 새로 만든다.

### 생성 전략

1. **1차 생성:** 8프레임을 한 번에 볼 수 있는 4열×2행 시트 1장을 생성한다.
2. **1차 검수:** 프레임 수, 중복, 방향, 실루엣, 알파, 스타일을 본다.
3. **수정:** 문제가 있는 항목 하나만 지정해 다중 턴 편집한다. 전체를 무조건 재생성하지 않는다.

5. **시트 일관성 실패 시의 예외:** 가장 좋은 절정 프레임을 기준 이미지로 고정한 뒤, 같은 대화에서 나머지 프레임을 한 장씩 수정 생성한다. 이때도 최종 8장은 동일 캔버스와 피봇으로 후처리한다.

### 시각 언어

- 외곽은 짙은 녹색으로 배경에서 분리한다.
- 중간색은 밝은 연두, 핵은 아주 옅은 청록 또는 아이보리로 제한한다.
- 충돌 프레임에만 작은 따뜻한 노랑 하이라이트를 1회 허용한다.
- 모든 프레임에서 형태가 낮게 깔려야 한다. 캐릭터 머리 위로 솟는 오라가 아니다.
- 이슬 방울은 둥글고 굵게, 잔상은 짧고 방향성이 있어야 한다.
- 프레임 사이의 변화는 단순 확대가 아니라 **형성 → 전진 → 끝점 충돌 → 파편화**여야 한다.

- 실제 달팽이 껍질, 껍질 아이템, 잎 아이템, 재료 아이템
- 큰 마법진, 룬, 왕관, 보석, 우주·신성·전설급 오라

- 거대한 원형 회오리와 화면을 가득 채우는 폭발
- 3D 렌더, 사진 질감, 유화, 에어브러시형 AI 광택, 과도한 네온 블룸
- 텍스트, 프레임 번호, UI, 테두리 선, 워터마크
- 흰색·검정색·체커보드 배경

- 프레임마다 캔버스·원점·피봇·전체 배율이 흔들리는 결과

### 인게임 가독성 합격 기준

- 100% 축소 보기에서 F02→F05의 진행 방향이 오른쪽으로 읽힌다.
- 잔디와 모래 양쪽 배경에서 어두운 외곽과 밝은 핵이 모두 보인다.
- 달팽이 본체보다 약간 넓지만 플레이어 스킬보다 작다.
- F05 한 프레임만 봐도 충돌 순간임을 알 수 있다.
- 실루엣만 보면 낮은 지면 흔적이며, 칼바람·투사체·마법진으로 읽히지 않는다.
- 프레임을 순서대로 보면 달팽이의 느린 준비와 짧은 전진감이 함께 느껴진다.

## 10. [수정용 후속 프롬프트]

후속 프롬프트는 **새 대화를 열지 말고 첫 결과가 있는 같은 대화**에서 사용한다. 한 번에 한 문제만 수정하고, 잘 된 항목은 보존한다.

### 프레임 수가 부족하거나 중복됐을 때

~~~text
현재 결과의 색, 선명도, 이펙트 정체성은 유지하고 프레임 구성만 수정해 주세요. 정확히 4열×2행의 8프레임이 필요합니다. 비어 있는 셀, 합쳐진 셀, 중복 프레임이 없도록 하세요. 순서는 준비 시작 → 준비 축적 → 형성 시작 → 이동·성장 → 절정 직전 → 충돌 → 분해 → 소멸입니다. 모든 프레임은 서로 다른 동작 단계여야 하고 F00과 F07도 완전히 비어 있으면 안 됩니다. 다른 스타일 변경은 하지 마세요.
~~~

### 투명 배경이 제대로 나오지 않았을 때

~~~text
현재 8프레임의 형태, 색, 크기, 배치는 그대로 보존하고 배경과 알파만 수정해 주세요. 흰색, 검정색, 회색 체크무늬, 그림자판을 모두 제거하고 실제 RGBA 알파 투명 배경으로 만들어 주세요. 이펙트 내부의 밝은 아이보리 하이라이트는 지우지 말되, 바깥 배경 픽셀과 반투명 사각형은 없어야 합니다. 정확한 4×2 배열과 동일 캔버스를 유지하세요.
~~~

### 스타일이 메이플풍에서 벗어났을 때

~~~text
현재의 “이슬 미끄럼길” 동작과 8프레임 순서는 유지하고 렌더링 스타일만 다시 정리해 주세요. 사진·3D·유화·매끈한 AI 에어브러시 느낌을 제거하고, 작은 화면에서 읽히는 선명한 컬러 2D RPG 스킬 VFX로 바꾸세요. 짙은 외곽, 채도 높은 연두 중간색, 작은 청록/아이보리 핵의 3단 명암을 사용하고, 흐릿한 광무리 대신 굵고 정리된 형태와 짧은 파편을 사용하세요. 메이플스토리/MSW 계열의 시각 언어는 참고하되 첨부된 기존 스킬의 실루엣이나 프레임을 복제하지 마세요. 저레벨 일반 달팽이답게 작고 덜 화려하게 유지하세요.
~~~

### 프레임 간 중심축·크기가 흔들릴 때

~~~text
현재 디자인과 색은 유지하고 정렬만 수정해 주세요. 8개 셀 모두 같은 256×256 기준 캔버스 비율을 사용하고, 효과의 시작 원점을 각 셀의 x 25%, y 50% 위치에 고정하세요. 전체 배율과 선 굵기를 일관되게 유지하고, 진행 부분만 오른쪽으로 성장하게 하세요. 프레임마다 이펙트 전체가 위아래로 튀거나 좌우로 재배치되지 않아야 합니다. 각 셀 가장자리에는 동일한 투명 안전 여백을 두고 셀 경계를 넘지 마세요.
~~~

## 11. [MSW 반입 가이드]

이 절차는 완성 이미지가 채택된 뒤 수행한다. 이 문서 작성 시점에는 프로젝트 파일이나 Resource Storage를 변경하지 않았다.

### 11.1 원본 보존과 파일 확인

1. 외부 AI가 반환한 원본을 OUT_SNAIL_DEW_TRAIL_SHEET_ORIGINAL.png로 별도 보존한다.
2. 실제 알파 채널이 있는지 확인한다. 체크무늬가 픽셀로 그려져 있으면 반입하지 않는다.
3. 시트가 정확히 8셀인지, 셀 사이로 그림이 넘어가지 않는지 확인한다.
4. 원본과 수정 프롬프트, 수정 차수, 채택 이유를 함께 기록한다.

### 11.2 정규화와 분할

1. 채택 시트를 비율 왜곡 없이 1024×512 RGBA PNG로 맞춘다.
2. 4×2 격자로 정확히 분할해 아래 파일 8장을 만든다.

~~~text
snail_dew_trail_f00.png
snail_dew_trail_f01.png
snail_dew_trail_f02.png
snail_dew_trail_f03.png
snail_dew_trail_f04.png
snail_dew_trail_f05.png
snail_dew_trail_f06.png
snail_dew_trail_f07.png
~~~

3. 각 파일은 256×256 RGBA를 유지한다.
4. 자동 자르기나 프레임별 재중심화를 하지 않는다. 투명 여백도 애니메이션 정렬 정보다.
5. 모든 프레임에서 제안 원점 x=64, y=128이 같은지 오버레이로 확인한다.

### 11.3 Resource Storage 등록

1. Maker의 Resource Storage → 내 리소스 → sprite에서 파일을 **한 장씩** 등록한다.
2. 이름은 f00~f07 순서가 정렬되도록 동일 접두사를 사용한다.
3. 각 스프라이트의 상세/슬라이스 편집에서 피봇과 보이는 경계를 확인한다.
4. 자동 트리밍으로 피봇이 흔들리면 모든 프레임을 normalized 0.25, 0.50 기준으로 보정한다.
5. 8개 Sprite RUID를 매니페스트에 기록한다.

### 11.4 AnimationClip 구성

1. Window → Animation Clip Editor를 연다.
2. f00부터 f07까지 순서대로 한 장씩 추가한다.
3. 타임라인 순서를 확인하고, 초안으로 프레임당 약 0.07초를 사용한다.
4. 루프하지 않는 1회 재생으로 설정한다.
5. 에디터의 초록 십자선 기준으로 모든 프레임의 Offset이 흔들리지 않는지 확인한다.
6. 절정 F05가 너무 짧게 보이면 F05만 한 프레임 복사해 체감 시간을 늘릴 수 있다. 다만 원본 8장의 의미와 재생 프레임 수를 기록에 구분한다.
7. 이름 예시는 fx_mon_snail_dew_trail이다.
8. 업로드하고 발급된 AnimationClip RUID를 기록한다.

### 11.5 프로젝트 연결

현행 프로젝트의 우선 연결 경로는 다음과 같다.

~~~text
SkillTable.layer_ruids
  → GameData.BuildEffectLayers
  → SkillEffect.PlayCast
  → SkillEffect.SpawnLayer
  → skillcasteffect 모델 스폰
  → SpriteRendererComponent.SpriteRUID에 animationclip RUID 지정
~~~

신규 스킬을 실제 도입할 때는 기존 s_mon_snail을 덮어쓰지 말고 별도 ID s_mon_snail_dew_trail로 추가하는 방식을 우선 검토한다. 단일 신규 클립만 쓸 경우의 데이터 초안은 다음과 같다.

| SkillTable 필드 | 초안 |
|---|---|
| layer_ruids | 발급된 신규 AnimationClip RUID 1개 |
| layer_types | animationclip |
| layer_styles | clip |
| layer_delays | 0 |
| layer_durations | 0.56 |
| layer_scales | 0.65~0.85에서 Play 검증 |
| layer_offsets_x | 0 또는 시전 원점에 맞춘 소폭 보정 |
| layer_offsets_y | 0 또는 지면에 붙이는 소폭 음수 보정 |
| layer_drifts_x / y | 0 / 0. 이동은 클립 내부 프레임으로 표현 |

이 프로젝트에서 layer_ruids가 있으면 SkillEffect가 animationclip을 SpriteRendererComponent에 직접 넣어 재생한다. 따라서 신규 클립을 반드시 _EffectService에 별도 하드코딩할 필요는 없다.

_EffectService:PlayEffectAttached는 레이어가 비어 있고 effect_ruid를 쓰는 기존 단일 경로에 남아 있다. 파일럿에서 어느 경로를 쓸지는 **현행 데이터 일관성을 위해 layer_ruids 경로를 우선**하고, 단일 effect_ruid 경로가 필요할 때만 별도 비교한다.

### 11.6 Maker 반영·런타임 검증

1. Maker Refresh로 데이터와 리소스를 반영한다.
2. Build 로그에서 신규 SkillTable 행과 RUID 형식 오류가 없는지 확인한다.
3. Play에서 r_001 버섯마을 외곽과 r_006 작은 숲속 샛길을 각각 확인한다.
4. 오른쪽 시전과 왼쪽 시전을 모두 사용해 FlipX와 고정 원점을 확인한다.
5. 달팽이 몬스터가 사용할 때와 플레이어가 포획 스킬로 사용할 때 높이·크기가 같은 의도로 보이는지 확인한다.
6. 피해 판정과 시각 절정 F05가 같은 시점인지 확인한다.
7. 이펙트가 캐릭터 살짝 위에 뜨거나 지면 아래로 묻히면 layer_offsets_y와 AnimationClip Offset 중 한 곳만 조정한다. 두 곳을 동시에 움직이지 않는다.
8. 종료 후 잔류 엔티티나 반복 재생이 없는지 확인한다.
9. build/normal 로그와 양방향 캡처를 함께 남긴 뒤에만 채택한다.

### 11.7 아직 확정하지 않는 값

- 최종 AnimationClip RUID
- 최종 Sprite RUID 8개
- 최종 scale과 offset
- 정확한 피해 계수와 재사용 대기시간
- 기존 달팽이에게 두 번째 스킬로 부여할지, 플레이어 전용 파일럿 슬롯에서만 시험할지
- 기존 몸통 박치기와의 획득·장착 UI 관계

## 12. [검수 체크리스트]

### A. 파일·프레임

- [ ] 정확히 8프레임이다.
- [ ] F00~F07에 빈 프레임이 없다.
- [ ] 누락·중복·합쳐진 셀이 없다.
- [ ] 시트는 4×2이며 읽는 순서가 명확하다.
- [ ] 후처리 시트는 1024×512 RGBA다.
- [ ] 개별 파일은 모두 256×256 RGBA다.
- [ ] 흰색·검정색·체커보드가 픽셀로 남지 않았다.
- [ ] 각 셀의 효과가 경계를 넘지 않는다.
- [ ] 반투명 사각형이나 생성 잔여물이 없다.

### B. 정렬·애니메이션

- [ ] 모든 프레임의 시작 원점이 x=64, y=128에 고정되어 있다.
- [ ] 전체 배율과 선 굵기가 프레임마다 튀지 않는다.
- [ ] 오른쪽 진행 방향이 F02~F05에서 분명하다.
- [ ] 준비→형성→이동→충돌→분해→소멸이 순서대로 읽힌다.
- [ ] F05가 가장 강한 순간으로 읽힌다.
- [ ] F07이 잔류를 보여 주되 완전히 빈 프레임은 아니다.
- [ ] 단순 확대·축소 반복이 아니라 형태가 실제로 변화한다.

### C. 디자인

- [ ] 저레벨 달팽이 신규 스킬로 읽힌다.
- [ ] 지면에 낮게 깔린 이슬 흔적으로 읽힌다.
- [ ] 실제 껍질이나 재료 아이템으로 보이지 않는다.
- [ ] 검격·화살·마법진·거대 회오리로 보이지 않는다.
- [ ] 메이플스토리/MSW 계열의 선명한 2D 게임 VFX 언어가 느껴진다.
- [ ] 기존 참조 스킬을 직접 복제한 형태가 없다.
- [ ] 달팽이 본체보다 조금 넓고 플레이어 전직 스킬보다 작다.
- [ ] 색이 초록 하나로 뭉개지지 않고 3단 명암이 분리된다.
- [ ] 잔디와 모래 배경 양쪽에서 외곽과 밝은 핵이 보인다.
- [ ] 과도한 AI 광택, 무의미한 장식, 사진·3D 질감이 없다.

### D. MSW 반입

- [ ] Sprite 8장을 순서대로 등록할 수 있다.
- [ ] 모든 Sprite의 피봇과 Offset을 동일하게 맞출 수 있다.
- [ ] AnimationClip이 1회 재생되고 루프하지 않는다.
- [ ] AnimationClip RUID가 기록되었다.
- [ ] layer_ruids / layer_types / layer_styles 값이 서로 같은 개수다.
- [ ] 좌우 FlipX가 의도대로 동작한다.
- [ ] r_001과 r_006에서 높이·크기·가독성이 통과했다.
- [ ] 피해 시점과 F05 충돌 시점이 일치한다.
- [ ] build 오류와 런타임 경고가 없다.
- [ ] 종료 후 잔류 이펙트가 없다.

### 채택 판정

- A 또는 D에서 하나라도 실패하면 **반입 불가**다.
- B의 원점 흔들림, C의 아이템 오인, 기존 스킬 복제는 **재생성 또는 수동 수정 필수**다.
- 작은 색조 차이만 남았고 가독성·정렬이 통과하면 전체 재생성 대신 국소 수정한다.
- 최대 권장 생성 예산은 기본 생성 1회 + 문제별 수정 3회다. 그 이후에도 구조가 틀리면 같은 결과를 계속 수정하지 말고 가장 좋은 절정 프레임을 기준으로 프레임별 생성 방식으로 전환한다.

## 13. [이 파일럿을 다른 몬스터로 확장할 때 재사용 가능한 규칙]

### 항상 고정할 규칙

1. **한 번에 몬스터 1종·스킬 1개만** 다룬다.
2. 먼저 MonsterTable, RoomTable, AreaTable, SkillTable, 모델, 공식 MSW 리소스 팩을 교차 확인한다.
3. 확인된 사실과 창작 연결을 같은 문장 안에서 섞지 않는다.
4. 기존 스킬은 스타일만 참고하고 기능·실루엣·프레임 구도를 복제하지 않는다.
5. 현행 스킬과 신규 스킬의 차이를 공격자 이동, 판정 위치, 전투 역할 세 축으로 설명한다.
6. 참조 이미지는 3~5개로 제한하고 각각의 역할을 한 가지로 명시한다.
7. RUID만 외부 AI에 주지 말고 실제 프레임 이미지로 첨부한다.
8. 과거 실패 이미지는 기본 입력에서 제외하고, 특정 오류를 고치는 수정 턴에만 부정 예시로 사용한다.
9. 프레임 수, 단계, 방향, 캔버스, 원점, 투명 배경, 금지 요소를 생성 전에 고정한다.
10. 빈 프레임·누락·중복·불투명 배경은 디자인 취향이 아니라 즉시 탈락 조건이다.
11. 전체 재생성보다 한 문제씩 고치는 다중 턴 수정을 우선한다.
12. 생성 원본은 보존하고, MSW용 정규화·분할본을 별도로 만든다.
13. 프레임별 자동 트리밍을 금지하고 동일 피봇을 유지한다.
14. Resource Storage 업로드 후 발급된 RUID와 프롬프트 수정 이력을 기록한다.
15. 최종 채택은 Maker Play에서 양방향·대표 배경 2종·몬스터/플레이어 사용을 모두 확인한 뒤 결정한다.

### 확장 시 품질·비용 통제

- 첫 결과에서 **구조**가 맞고 색만 틀리면 색만 수정한다.
- 프레임 수·배열·원점이 틀리면 구조 수정 프롬프트를 먼저 쓴다.
- 스킬 정체성이 틀리면 과거 실패 이미지를 부정 예시로 한 번만 추가한다.
- 참조 이미지를 계속 늘리지 않는다. 모델이 어느 이미지를 따라야 할지 흐려진다.
- 저레벨·일반·엘리트·보스별로 최대 화면 점유율과 색 수를 따로 정한다.
- 스킬당 “기본 1회 + 국소 수정 최대 3회”를 작업 예산으로 잡고, 실패가 반복되면 프레임별 생성 또는 수동 후처리로 전환한다.
- 새 몬스터로 넘어가기 전에 이번 파일럿의 실제 생성 시간, 수정 횟수, 분할 시간, 업로드 시간, Maker 검증 시간을 기록한다. 이것이 1~200 전체 확장의 현실적인 처리량 산정 기준이 된다.

### 이 파일럿의 성공 조건

다음 네 가지가 모두 충족되면 다른 몬스터로 확장할 수 있다.

1. 8프레임 시트를 외부 AI에서 얻고 동일 캔버스로 안정적으로 분할할 수 있다.
2. 결과가 폐기된 껍질 아이템형 이펙트와 명확히 다르고, 이슬 미끄럼길로 읽힌다.
3. MSW AnimationClip으로 등록해 현행 layer_ruids 경로에서 양방향 1회 재생할 수 있다.
4. r_001과 r_006에서 저레벨 가독성, 피봇, 타격 시점이 검수 체크리스트를 통과한다.

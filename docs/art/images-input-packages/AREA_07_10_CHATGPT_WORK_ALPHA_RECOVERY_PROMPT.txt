4. 알파 복구 원칙
==================================================

색상 전체를 일괄 삭제하지 마세요. 단순 RGB→RGBA 변환도 투명 배경 복구가 아닙니다.

알파 복구는 다음 기준으로 수행하세요.

- 원본 시트의 네 모서리와 외곽에서 실제 매트색을 측정합니다.
- 배경과 연결된 영역을 기준으로 매트 마스크를 만듭니다.
- 완전 불투명한 내부 픽셀의 의도된 색은 보존합니다.
- 매트 제거와 색 오염 완화는 반투명 경계 픽셀에 집중합니다.
- 불꽃, 별빛, 얼음, 먹물의 밝은 코어와 반투명 발광을 완전 투명 또는 완전 불투명으로 뭉개지 마세요.
- 작은 파편과 해체 프레임을 잡음으로 판단해 삭제하지 마세요.
- 배경과 연결되지 않은 내부 색을 매트색과 비슷하다는 이유로 제거하지 마세요.
- 결과는 straight-alpha RGBA PNG로 저장하세요.
- 완전 투명 픽셀의 RGB 잔류가 합성 시 색 테두리를 만들지 않도록 정리하세요.

가능하면 기존 원화에 대해 결정론적인 기계적 알파 복구를 먼저 수행하세요. 이 처리는 허용됩니다.
Python으로 새로운 그림, 파편, 발광, 실루엣을 그리는 것은 금지합니다.

알파 복구 후 다음 세 합성본을 같은 배율과 같은 위치로 생성하세요.

- 순검정 #000000
- 중간 회색 #808080
- 순백색 #FFFFFF

세 합성본에서 형태는 같아야 하며, 배경색에 따라 자홍·녹색·청록색 테두리가 새로 나타나거나 사라지면 FAIL입니다.

==================================================
5. 크로마 오염 판정 기준 수정
==================================================

다음 판정 방식은 금지합니다.

- 이미지 전체에서 녹색·자홍색·청록색 픽셀 수를 세어 FAIL
- 스킬의 의도된 팔레트에 포함된 색을 크로마색과 같다는 이유로 FAIL
- 불투명 내부 픽셀을 외곽 매트 잔류로 판정
- 임계값만 바꿔 동일한 크로마 재생성을 반복

다음 조건을 모두 만족하는 픽셀 군집만 크로마 오염으로 판정하세요.

1. 원본 매트색과 직접 관련된 색 편향이 있고
2. 투명 또는 반투명 외곽 경계에 있으며
3. 배경 연결 영역이나 그 바로 안쪽에 있고
4. 검정·회색·흰색 합성 중 하나 이상에서 부자연스러운 색 띠로 보이며
5. MONSTER_INFO, GENERATION_SPEC, 참조 매핑에서 의도된 효과색으로 설명되지 않습니다.

자동 수치 검사는 보조 증거입니다. 최종 판정은 실제 합성 이미지의 외곽 상태와 명세를 함께 확인해 내리세요.

6. 앵커 품질 게이트
==================================================

각 앵커마다 다음을 모두 확인하세요.

1. INPUT의 monster_id, skill_id, 스킬명, 역할, 동작과 일치
2. MONSTER_IMAGE의 소재와 정체성이 효과에 반영됨
3. 몬스터 본체, 텍스트, 번호, UI 프레임, 체커보드가 들어가지 않음
4. 어두운 외곽→명확한 중간톤→밝은 코어의 다층 명암
5. 실제 게임 프레임 자산으로 읽히는 준비→성장→절정→해체→fade 흐름
6. 같은 캔버스, 기준축, 중심축과 안정된 크기 변화
7. 잘림, 다른 셀 조각, 프레임 간 순간이동이 없음
8. 실제 RGBA와 유효한 가변 alpha가 존재
9. 검정·회색·흰색 합성에서 매트색 테두리가 없음
10. 작은 크기에서도 핵심 실루엣을 식별할 수 있음

원화가 통과하고 알파만 실패하면 ALPHA_EDGE_RECOVERY 대상으로 기록하세요.
원화 자체가 실패할 때만 ART_REGENERATION_REQUIRED로 기록하고 해당 앵커만 다시 생성하세요.

한 앵커가 실패하면 그 Area의 나머지 제작은 멈추되, 다른 Area의 검증과 제작은 계속할 수 있습니다.

7. 앵커 통과 후 전체 제작
==================================================

앵커가 통과한 Area는 INPUT V2.4의 모든 NEW_ART 역할을 빠짐없이 제작하세요.

- monster_id, skill_id, 스킬명, 타입, 효과와 동작을 변경하지 마세요.
- 각 몬스터의 실제 MONSTER_IMAGE와 GENERATION_SPEC을 사용하세요.
- 각 스킬에 매핑된 기존 MapleStory/MSW 참조는 렌더링 문법과 애니메이션 구성 참고에만 사용하세요.
- 기존 스킬의 고유 실루엣이나 내용을 복제하지 마세요.
- AREA 00의 품질, 명암 구조, 알파 마감, 프레임 리듬을 기준으로 삼되 AREA 00의 팔레트와 모양은 복제하지 마세요.
- 단일 포스터나 키비주얼이 아니라 frame-separated 게임용 VFX로 만드세요.
- 같은 스킬의 모든 프레임은 동일 canvas, 기준축, 중심축을 유지하세요.
- ICON은 VFX의 핵심 모티브와 색·형태 언어를 공유해야 합니다.
- VFX 완성도를 먼저 판정한 뒤 ICON을 제작하세요.

새 스킬 제작에서도 매트색은 스킬의 의도된 팔레트와 겹치지 않도록 자산별로 선택하세요.
발광 때문에 매트 오염이 생기면 매트색만 바꿔 무한 재생성하지 말고, 원화를 보존한 경계 알파 복구를 적용하세요.

8. 기록과 중단 규칙
==================================================

각 Area의 새 run_id 아래에 WORK_STATE.json을 계속 갱신하세요.

반드시 기록할 항목:

- Area 및 run_id
- 읽은 INPUT·참조 파일 경로와 SHA-256
- 처리 중인 monster_id / skill_id / 역할 / 프레임
- 원화 판정 PASS 또는 FAIL과 근거
- ALPHA_EDGE_RECOVERY 또는 ART_REGENERATION_REQUIRED

- 완료한 VFX와 ICON 수
- 남은 작업
- BLOCKED 사유

같은 방식의 크로마 재시도가 두 번 실패하면 세 번째 색상으로 반복하지 마세요.
원화 보존형 알파 복구로 전환하세요.
알파 복구도 실패하고 native 이미지 편집으로도 깨끗한 외곽을 만들 수 없을 때만 해당 Area를 BLOCKED로 기록하세요.

BLOCKED인 Area의 정상 OUTPUT ZIP을 만들지 마세요.
완료된 다른 Area의 ZIP 제작까지 취소하지 마세요.

- OUTPUT ZIP

ZIP에는 실제 최종 VFX 프레임, ICON, Preview, Manifest, RESULT_INFO를 포함하세요.
이미지나 보고서만 만들고 완료했다고 하지 마세요.

최종 응답은 다음만 간단히 보고하세요.

- AREA 07~10 각각의 앵커 통과 여부

- 각 Area 전체 제작 여부
- BLOCKED가 남았다면 정확한 대상과 이유
- 실제 OUTPUT ZIP의 절대 경로

AREA 07~10 작업이 끝나면 멈추세요. AREA 11 이후를 자동으로 시작하지 마세요.

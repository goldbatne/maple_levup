# 원화 스타일과 알파 손상 분리

## 직접RGBA가 아닌 이유
최초주황버섯ICON은RGBA였지만CAST는RGB검정, RESTART/ANCHOR투명요청은RGB체커를반환했다. 동일도구호출명에서도결과가달랐다. nativealpha출력가능성을전부부정하거나모델변경때문이라고확정할수없다. GRAMMAR는사용자가단색배경후처리를허용한뒤전환했다.

## AREA00과 같았는가
최초AREA00: 최종PNG49개RGBA는확인, 생성원본/추정방법UNKNOWN. refinement: 검정발광가장자리만역합성하고원래중앙알파는보존. AREA01: 새원본전체에가정한알파를적용. 적용범위와보존할실제전경이전혀다르다.

## 수식으로 확인한 손상
한배경의RGB는 C=alpha*F+(1-alpha)*B다. RGB관측3개에미지수전경RGB3개와alpha1개이므로추가가정없이유일하게복원되지않는다.

- 최초: 외부연결저밝기만fade하고그외불투명으로만드는임계32수식. 부드러운가루전체의원래투과율을알수없으며불투명영역을과대설정할수있다.
- RESTART: /126과/253은서로다른불투명도가정을입힌다. 검정배경재합성이비슷해도흰배경에서재질이동일하다는뜻이아니다.
- GRAMMAR blue: foreground B=.65min(R,G) 가정. 밝은중간톤이클리핑/탈색될수있음. 이번정량조건에서크림→녹색우세전환은0픽셀이므로분홍과같은녹색원인이라고뭉치지않는다.
- GRAMMAR magenta: foreground B=.68G 가정. 실제원본(456,528)의RGB[251,230,183]이역합성에서RGBA[251,255,175,228]로변함. 크림조건(R>G+.02,G>.65,B<G)119254픽셀중3567개가G>R+.01로역전. **단순스타일평가가아닌코드에의한색상손상증거**다. 리사이즈이전계산이며ALPHA_NUMERIC.json에기록.
- 두번째원본은균일magenta요청에도실제배경변동이있다. 고정[1,0,1]차감은저알파색잔류를만들고384²패딩안에서직사각형으로보인다. 마스크가전경만다루지않아배경도반투명으로남음.

## 원화 자체는 좋았는가
아니다. 최초CAST원본에이미굵은윤곽·광택물방울·과다분진이있다. ANCHOR의세갈래장식도처리전원본에있다. GRAMMARblue는소재가포자구름에가까워졌지만너무많은점과거친경계가있고magenta는고형구름/크림장식같은밀도차이가있다. 알파를완벽히분리해도이형태·프레임미완성은해결되지않는다. 반대로이주관적형태판단을근거로알파코드손상을숨겨서도안된다.

## 1. 프로젝트 개요

### 1.1 게임이 무엇인가 (기획서 §1)

**성장할수록 세계가 열리는, 방(房) 단위 탑다운 탐험 성장 RPG.**

화면 하나가 방 하나이고, 가장자리로 나가면 다음 방으로 넘어간다. 방 사이에는 잠긴 문이 있고,
그 문은 스탯·스킬·환생 같은 **성장의 결과로만** 열린다. 그래서 성장의 보상이 숫자가 아니라
**새로운 땅**이 된다. 비주얼이 아니라 피처폰 RPG의 **구조적 감성**(방 단위 이동, 압축된 밀도,
단순하지만 리듬 있는 전투)을 재현하는 것이 목표다.

층위가 둘로 나뉘어 있고, 이 분업이 모든 기능 판단의 기준이다.

| 층위 | 정체성 | 레퍼런스 | 역할 |
|---|---|---|---|
| **코어** (왜 하는가) | 세계를 한 방씩 헤쳐나가는 맛 | 영웅서기·이카루스 전기 | 플레이의 목적 |
| **엔진** (무엇으로 굴리나) | 숫자가 오르는 성장의 손맛 | Re:END | 플레이의 동력 |

> 리트머스: *"이건 코어를 강화하나, 엔진을 강화하나?"* 둘 다 아니면 넣지 않는다.

개발 형태: 1인 + AI 협업 / 목표: 2개월 수직 슬라이스 / 플랫폼: 메이플스토리 월드 (mLua).

### 4.8 빌드 소프트락 — 2026-08-12 발견, 같은 날 해소 ✅

**있었던 문제**: 수치 게이트가 "공격력"이 아니라 `ATK`라는 스탯 하나를 문자로 검사했다.
r_02는 `stat / ATK / 20`이었는데, 2026-08-08에 자동 공격 계수를 `max(ATK, INT)`로 바꾼 뒤
게이트를 다시 보지 않았다. 그래서 **INT 빌드는 전투가 성립하는데 게이트만 못 넘었다.**
재분배 기능이 없고(`ResetRun`은 환생만 호출) 보스가 r_02 뒤에 있어 환생 조건도 못 채우므로
**복구 경로가 없는 영구 차단**이었다.

**해소**: 게이트를 `STAT_TOTAL / 10`(분배한 포인트 총합)으로 바꿨다. 어디에 넣었는지를
묻지 않으므로 어떤 빌드든 같은 시점에 열린다. 기획서 §3.2에 근거를 남겼다.

**남는 함정**: 스탯을 지정하는 게이트(`gate_key=ATK` 등)는 판정 코드가 그대로 있고
필요하면 쓸 수 있다. 단 **우회로가 있는 방에만 쓴다.** 외길에 달면 같은 덫이 다시 생긴다.
재분배 기능이 없다는 전제는 그대로다.

### 4.9 포션에 쿨다운이 없다 (T13-7)

연타로 여러 개를 한 번에 마실 수 있다. 악용 소지는 없다고 봤다 — 낭비는 본인 손해이고,
만피에서는 아예 소모되지 않는다(효과 먼저·소모 나중). 다만 원작 메이플에는 짧은 쿨이 있으므로

`PlayerInventory.UseItem`의 맨 앞이고, 값은 `GameBalance.csv`에 키를 하나 더 두면 된다.

## 7. 주의할 것

### 7.1 지켜야 할 규칙 (요약 — 정본은 CLAUDE.md · AGENTS.md)

1. **실행공간을 상단 주석에 명시** (`-- @서버` / `-- @클라이언트`).
2. **반드시 서버에서**: 데미지 계산, 스탯 분배, 경험치·레벨, 포획 판정, 환생, 저장.
   클라이언트는 입력과 연출만.
3. **수치 하드코딩 금지** — 데이터 테이블 또는 상수 모듈에서 읽는다.
4. **존재하지 않는 API 추측 금지** — `Environment/NativeScripts/**/*.d.mlua`를 먼저 읽는다.
5. **데이터 분리** — 영구(컬렉션·슬롯 수·환생 횟수·개방 지역) vs 회차(레벨·EXP·스탯·직업).
6. **게임 설계는 임의로 바꾸지 않는다.** 구현이 어려우면 문서를 고치지 말고 대안을 설명해
   승인을 받는다. "복잡해서 단순화했다"는 사후 통보 금지.
7. **한 번에 한 태스크.** 완료 → 직접 실행 검증 → 커밋 → 보고 → 다음.
   커밋은 "작동하는 상태"에서만.
8. **워크스페이스 탐색은 Glob/Read/Grep**로. 셸 `ls`/`cat`/`grep`/`find` 금지
   (Windows·macOS 셸이 갈라지고 `D:\경로`가 bash에서 깨진다).
9. **`.map`/`.model`/`.ui`는 빌더로만** (`MapBuilder`/`ModelBuilder`/`UIBuilder`). 원본 JSON 직접 수정 금지.
10. **런타임 결과는 MCP 호출 없이 주장하지 않는다.** "동작한다"는 `play` → `logs`를 거친 뒤에만.

### 7.2 함정 — 에러 없이 조용히 실패하는 지점

전부 이 프로젝트에서 **실제로 겪은** 것들이다.

| 증상 | 원인 | 대응 |

| 새 맵이 아예 로드되지 않는다 | `Global/SectorConfig.config`에 `map://맵이름`을 등록하지 않았다 | 맵 생성 시 함께 등록 |
| 포탈이 아무 데도 가지 않는다 | `RoomPortal.direction`이 비어 있다 | `east`/`west`/`north`/`south` 중 하나를 반드시 설정 |
| 신규 계정이 엉뚱한 방에서 시작한다 | **`is_start`는 최초 스폰을 결정하지 않는다.** 사망 복귀·환생 복귀·보스방 귀환·`RestoreRoom` 네 곳이 읽을 뿐이고, 최초 스폰은 **Maker의 월드 시작 맵** 설정을 따른다 | 저장된 방이 없을 때 `is_start`로 보내는 분기가 `RestoreRoom`에 있다 (T13-1d). 월드 시작 맵을 바꾸려면 Maker에서 해야 한다 |
| 방에 들어갔다가 **즉시 튕겨 나온다** | 도착 좌표가 **목적지 맵의 타일 밖**이다. `RoomTable.portal_x`가 그 맵 폭과 안 맞으면 타일 경계로 밀려나 반대편 포탈 트리거에 얹힌다 (마을 14칸 폭에 13을 쓰면 x=10.5) | 새 맵을 만들면 `portal_x`/`portal_y`를 그 맵 포탈 좌표로 맞춘다. 그리고 트리거를 물는 컴포넌트는 **전부** `_PortalGuard:CanPass`를 확인해야 한다 |
| 방 데이터를 못 찾는다 | **맵 이름과 `RoomTable.map_name`이 달라졌다** (`RoomSpawner`·`RoomMonster`·`RoomPortal`·`ReturnPortal`·`PlayerDBManager`가 모두 이 규칙에 의존) | 같게 유지 |
| 엔티티가 안 움직인다 / `[LEA-3004]` | `TileMapMode` ↔ Body 컴포넌트 불일치. **이 프로젝트는 전 맵 RectTile(=1) → `KinematicbodyComponent`** | 맵 모드를 먼저 확인 |
| `SyncTable` 초기값이 사라진다 | `SyncTable` 프로퍼티에 기본값 리터럴을 쓸 수 없다 | `OnBeginPlay`에서 채운다 |
| 빌드 로그가 비었는데 게임이 깨져 있다 | **빈 build 로그 ≠ 빌드 성공.** mlua 변환 에러는 normal 로그에만 뜬다 | `logs(build)` + `logs(normal)` 둘 다 본다 |
| 타일을 못 깐다 | 타일 칠하기·맵 모드 전환은 `MapBuilder` 커버리지 밖이다 | Maker UI에서 한다 |
| 안내문이 아래 버튼 위로 흘러넘친다 | 텍스트 RectSize는 **줄 수만큼 자라지 않는다.** 넘친 글자는 잘리지 않고 그려져 이웃 위에 얹힌다 | 줄 수 × 글자크기로 높이를 잡는다. `ui_lint` **L023**이 겹침을 잡아 준다 (`KeyConfig/Hint` 실측) |
| CSV 마지막 컬럼의 글이 중간에서 잘린다 | **`note` 안의 쉼표가 컬럼 구분자로 읽힌다.** Maker가 재직렬화할 때 넘친 칸을 버려서 뒷글이 사라진다 (`max(ATK, INT)`라고 썼다가 `max(ATK`만 남았다 — T13-2 실측) | 셀 안에 쉼표를 쓰지 않는다. 나열은 `/`나 `|`로 |
| `.csv`/`.model`/`.ui`가 전 줄 변경으로 잡힌다 | Maker가 저장 시 UTF-8 BOM + CRLF로 재직렬화한다. 내용은 동일 | `[chore]` 커밋으로 분리 |
| **검증 스크립트가 아무것도 바꾸지 않는데 에러도 없다** | `maker_execute_script`의 실행 위치 파라미터는 **`context`**다. `target`처럼 없는 이름을 주면 조용히 무시되고 **클라이언트에서 돈다.** 그러면 `AddItem`·`SetEquipSlot` 같은 `ServerOnly` 호출이 전부 **에러 없이 무시된다** — 로그는 찍히는데 값만 안 변해서 "코드가 틀렸다"로 오진하게 된다 (T15-1 실측) | `context: "server_main"`을 준다. 응답의 `"context"` 필드와 로그의 `isGeneratedFromServer`로 어디서 돌았는지 확인한다 |
| 서버 스크립트에서 플레이어를 못 찾는다 | **`_UserService:GetUsers()`는 없다** (`[LEA-2011] 'GetUsers'은 nil입니다`) | `GetUsersByMapName(맵이름)` 또는 `GetUsersByMapComponent`를 쓴다 |
| **스킬 버튼을 눌러도 아무 일이 없는데 에러도 없다** | 데이터에서 스킬을 지웠는데 **옛 세이브의 장착 슬롯에는 그대로 남는다.** `PlayerAttack.UseSkill`이 `GetSkill(nil)`에서 조용히 `return false` 해서 **죽은 버튼**이 된다 (T17-1 실측: `s_mon_slime`·`s_mon_skeleton`) | `PlayerSkillSlots.DropUnknownSkills`가 로드 시 걷어낸다. **몬스터·스킬을 표에서 지울 때는 장착·인벤토리에 남은 참조를 반드시 같이 본다** |
| **창이 다른 창 뒤에 깔린다** | `.ui`끼리의 z-order는 **`UIGroupComponent.GroupOrder`**가 정하고, `GroupType`이 다르면 레이어부터 갈린다(1=HUD, 2=팝업). 환생 창이 `GroupType=1 / GroupOrder=1`이라 가방·퀵슬롯·진척도가 전부 위에 있었다 (T18-3 실측) | 모달·팝업은 `GroupType=2` + 다른 창보다 높은 `GroupOrder`. 현재 배치는 HUD 2~7 / 창 8~14 / **환생 모달 30** |
| **`model://...`에 `LWA-4012` 경고가 뜬다** | 값이 안 먹은 것처럼 보이지만 **무해하다.** `Hero.model`의 `script.MonsterAttack.AttackInterval`이 계속 경고를 냈는데, 런타임에서 스폰해 읽어 보니 `0.5`(스크립트 기본값 0.03이 아니라 모델 값)로 정상 적용돼 있었다. 버섯 모델과 값 항목이 바이트 단위로 같은데도 히어로만 경고가 난다 — 원인은 못 찾았다 | 값이 실제로 먹었는지 **런타임에서 읽어 확인**하고, 먹었으면 넘어간다. 경고만 보고 모델을 고치면 헛수고다 |
| **`placeModel`로 놓았는데 엔티티가 (0,0,0)에 선다** | `.model`이 `TransformComponent.Position` 값을 들고 있으면 `placeModel`이 **모델 Values를 나중에 덮어써서** 호출부의 `pos`가 사라진다 (T16-3d 실측: `(-11,6)`으로 놓았는데 `(0,0,0)`) | 템플릿에 월드 좌표를 박지 않는다. 위치는 배치하는 쪽(`.map`)이 정한다. 이미 박혀 있으면 `removeValue('MOD.Core.TransformComponent','Position')` 후 다시 배치 |
| **아바타 몬스터가 붙어 있는데 데미지가 0인데 에러도 없다** | `MonsterAttack.OnBeginPlay`가 `SpriteRendererComponent.SpriteRUID`로 클립을 읽어 공격 상자를 유도하고, **그 `PreloadAsync` 콜백 안에서 공격 타이머를 시작**한다. 아바타 몬스터는 스프라이트가 없어 콜백이 아예 안 돌고, 타이머가 시작되지 않는다 (T16-3b 실측) | 스프라이트가 없으면 사람 크기 상자(`0.67×1.42`)로 갈라 타이머를 직접 건다. T10-3의 "가드에 걸려 타이머가 안 돌던" 사고와 같은 모양이라 같은 자리를 또 본다 |
| **아바타 코스튬이 조용히 안 입혀진다** | 리소스 검색의 `category: weapon`은 **한손 슬롯**(`CustomOneHandedWeaponEquip`)이다. 두손 슬롯에 넣으면 `[LEA-3005] 유효한 아이템 카테고리가 아닙니다`가 뜨고 그 칸만 빈다 (T16-3b 실측) | 검색 결과의 `category`를 `msw-avatar`의 슬롯 표에 그대로 대응시킨다. `twohandweapon`은 별도 카테고리다 |
| **새 맵에서 몬스터가 화면 밖·타일 밖에 선다** | `RoomSpawner`의 스폰 영역 기본값이 **28×16 맵 기준**(`x -10~10 / y -4~6`)이다. 16×9인 `mapjob`에서는 맵 밖으로 나간다 (실측: 히어로가 `x=8.18`) | 새 맵을 만들면 그 맵의 `RoomSpawner` 값을 타일 범위 안으로 좁힌다. **도착 좌표(`portal_x/y`)를 덮지 않게** — 덮으면 보스가 입구에 서서 들어서자마자 죽인다 |
| **아이템 아이콘이 칸 밖으로 삐져나온다 (RectTransform은 멀쩡한데)** | `SpriteGUIRendererComponent.PreserveSprite = AspectOnly(1)`는 비율을 지키는 대신 **위치를 스프라이트 자신의 pivot에 맞춰 잡는다.** 원작 아이템 스프라이트는 pivot이 그림 밖에 있어서(빨간 포션 28×28에 `(-3,-3)`, 목걸이 `(-1,-6)`) `(0.5 − nx) × 폭`만큼 밀려 그려진다. **좌표로 재면 사각형은 칸 안에 있다** — 그려지는 그림만 나간다 (T17-4c 실측) | `PreserveSprite = None(0)`. RectSize에 맞춰 그려져 칸 안에 들어온다. 대가는 비율이 안 지켜지는 것이라 **아이콘 칸을 원본 비율에 가깝게** 잡는다. `Type`(Sliced/Simple)은 상관없다 |
| **맵 입장을 `UserEnterEvent`로 잡으려는데 안 온다** | 텔레포트(`_TeleportService:TeleportToMapPosition`)로 맵을 옮기면 그 맵 스포너에게 이벤트가 오지 않았다. 게다가 맵이 로드되는 시점(`OnBeginPlay`)에는 `GetUsersByMapName`이 아직 **0**을 돌려준다 — 그래서 "이미 있는 사람" 검사도 헛돈다 (T16-1 실측) | **방에 있는 사람 목록의 상승 엣지**를 짧은 주기로 직접 본다 (`RoomSpawner.CheckBossEntry`). 참고: T16-1 전까지 보스를 실제로 세우던 것은 `OnUserEnter`가 아니라 3초 주기 리필이었다 |

### 7.3 검증 루프

```
stop → clear_logs → refresh → logs(build) → play → logs(normal) → stop
```

`clear_logs`를 **읽기 전에** 부르면 관찰 한 라운드를 날린다. 순서를 지킨다.

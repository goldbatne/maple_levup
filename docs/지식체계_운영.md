# 지식 체계 운영 규칙

> 갱신: 2026-09-07 · 목적: GPT-5.6 Sol 같은 장문맥 에이전트도 필요한 정보만 빠르게 찾게 한다.

## 1. 원칙

- 큰 문맥 창은 모든 기록을 매번 넣는 용도가 아니다. 얇은 인덱스에서 필요한 정본으로 내려가는 점진적 조회를 기본으로 한다.
- MSW 플랫폼 지식은 공식 Skill과 MCP에 맡기고 프로젝트 문서에 복제하지 않는다.
- 현재 사실, 설계 의도, 작업 중 상태, 역사 기록을 한 파일에 섞지 않는다.
- Git이 변경 이력을 보존하므로 작업별 장문 일지를 활성 문서에 누적하지 않는다.

## 2. 문서 수명 주기

| 종류 | 위치 | 갱신 시점 | 금지 사항 |
|---|---|---|---|
| 진입점 | `docs/README.md` | 정본 추가·이동 시 | 구현 세부 누적 |
| 현재 상태 | `프로젝트_현황.md` | 기능 검증 완료 시 | 미검증 사실을 완료로 표기 |
| 작업 인수인계 | `인수인계_현재상태.md` | 작업 시작·종료·중단 시 | 전체 역사 복제 |
| 설계 정본 | 기획·밸런스·지역 문서 | 대표 결정 변경 시 | 취소된 안을 현행과 혼재 |
| 결정 기록 | `결정기록.md` | 되돌리기 어려운 결정 시 | 실행 로그 전문 |
| 보고서·역사 | `archive/` | 작업 종료 시 이동 | 기본 읽기 경로에 포함 |

## 3. 충돌 처리

1. CSV·스크립트와 문서가 다르면 먼저 자동 검증으로 실제 값을 확인한다.
2. Maker에서만 알 수 있는 것은 Refresh → Play → 로그/화면 순으로 확인한다.
3. 구현이 의도대로면 문서를 고친다. 구현이 의도와 다르면 임의 수정하지 말고 차이를 작업 항목으로 남긴다.
4. 폐기된 내용은 삭제 대신 `archive/` 또는 결정 기록의 ‘대체됨’ 항목으로 보존한다.

## 4. 작업 종료 체크

- `프로젝트_현황.md`에는 검증을 통과한 결과만 반영한다.
- 남은 일은 `인수인계_현재상태.md`에 한 번만 쓴다.
- 결정이 바뀌었으면 `결정기록.md`와 관련 정본을 함께 고친다.
- `node docs/tools/verify-knowledge-base.cjs`와 관련 콘텐츠 검증기를 실행한다.
- 런타임 동작을 주장할 때는 Maker MCP 증거를 남긴다.
- 커밋/PR 설명은 결과·검증·남은 위험을 요약하고 장문 로그는 링크로 연결한다.

## 5. AI ToolKit 경계

- 루트 `AGENTS.md`의 관리 블록은 공식 도구가 갱신하므로 프로젝트 설명을 복제하지 않는다.
- `.agents/`, `.codex/`, `.mswai/`는 설치·캐시 영역이다. 프로젝트 고유 지식은 `docs/`에 둔다.
- 비밀정보가 들어갈 수 있는 `.mcp.json`은 커밋하지 않는다.
- MCP 연결이 없으면 런타임 검증을 했다고 쓰지 않는다.
